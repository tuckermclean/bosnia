**Owns:** `package.json`, `package-lock.json`, `tsconfig.base.json`

## Purpose

Imported from the code. The root `package.json` makes the repository an npm workspace named `bosanski`
(private, version 0.1.0) whose members are `backend` and `content`; `app/` and `voice-agent/` are not members
(`app/` has its own lockfile and its own `npm ci`). It requires `node >=20`, and defines three scripts: `test`
runs only the backend's tests (`npm run test --workspace backend`), `backend` starts the backend's dev server,
and `content` forwards to the content workspace's scripts. `package-lock.json` (lockfile version 3) pins the
dependency tree of the root and both workspaces; CI installs it with `npm ci`, as does the backend image build.
`tsconfig.base.json` holds the compiler options that `backend/tsconfig.json` and `content/tsconfig.json`
extend: target and `lib` ES2022, `NodeNext` modules and resolution, `strict`, `noUncheckedIndexedAccess`,
`noImplicitOverride`, `esModuleInterop`, `skipLibCheck`, `forceConsistentCasingInFileNames`,
`resolveJsonModule`, declarations and source maps. (`app/tsconfig.json` extends Expo's base, not this file.)

## Tests

No test reads these files. They are exercised by every run of the backend and content suites: the gate's
`npm test -w @bosanski/backend` and `npm run test -w @bosanski/content` address the packages by workspace name,
which resolves only through the root `workspaces`. CI's `npm ci` steps check that the lockfile matches the
manifests, and CI's typecheck steps (`npm run typecheck -w @bosanski/backend`, `-w @bosanski/content`) compile
under `tsconfig.base.json`; neither is a test.

## Risks

- `engines` allows Node 20, but `backend/src/env.ts` uses `process.loadEnvFile()` (Node 20.12 and later) and CI
  runs Node 22 (`SPEC.md`, OD9). `env.ts` calls it inside a try/catch, so an older Node 20 boots but silently
  skips loading `.env`.
- The root `npm test` runs the backend alone, so a reader who runs it believes the whole suite passed; the
  gate command is the whole suite.
- A dependency change in a workspace changes `package-lock.json` too: a node that bumps a backend or content
  dependency changes this node's files (priority 2, dependencies, in `SPEC.md`).
- The lockfile is generated by npm; editing it by hand rather than through `npm install` can break `npm ci`.
